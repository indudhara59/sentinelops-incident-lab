# Two-minute portfolio demo

Prepare an authenticated demo account and a seeded Midnight Latency session. Use browser zoom suitable for recording, hide personal bookmarks, and show the simulated-environment badge.

| Time      | Action and narration                                                                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:08 | Open the homepage. “SentinelOps is a safe, fictional incident-response lab with deterministic telemetry and evidence-based reports.”                                    |
| 0:08–0:15 | Open Scenarios and briefly use a filter. “The catalog covers latency, queues, memory, defensive authentication analysis, and cascading failure.”                        |
| 0:15–0:23 | Select **The Midnight Latency Incident**, open its briefing, and point to impact, alerts, topology, rules, and learning objectives.                                     |
| 0:23–0:30 | Start the investigation. “FastAPI owns this ephemeral session; the browser receives bounded telemetry over a capability-protected WebSocket.”                           |
| 0:30–0:38 | Show the service map and Alerts. Select **Order service** using its topology control.                                                                                   |
| 0:38–0:47 | Open Metrics. Highlight rising order latency and database-pool utilization, then show the accessible data-table alternative.                                            |
| 0:47–0:56 | Open a slow Trace. Point to database connection waiting on the critical path without declaring the answer.                                                              |
| 0:56–1:04 | Follow the trace into correlated Logs using the preserved trace/service filters.                                                                                        |
| 1:04–1:11 | Open Deployments and show the fictional order-service version released near incident onset.                                                                             |
| 1:11–1:20 | Collect one metric range, span, and log as evidence. Add a short annotation.                                                                                            |
| 1:20–1:28 | Create “Deployment introduced connection retention” as a hypothesis and attach the evidence.                                                                            |
| 1:28–1:36 | Open Actions, review rollback risk, confirm the simulated rollback, and show its timeline entry.                                                                        |
| 1:36–1:45 | Advance the stable window and verify latency, error rate, pool usage, and successful traces recovered.                                                                  |
| 1:45–1:54 | Submit the evidence-linked conclusion and concise incident documentation. Open the scored report and show the transparent category breakdown.                           |
| 1:54–2:00 | Open Dashboard history. “Signed-in users retain bounded summaries and exact scenario versions in Atlas; raw telemetry and real infrastructure never enter the product.” |

Do not imply the score is a certification or employment assessment. If a hosted API is unavailable during recording, pause and fix it; do not present local fallback as the deployed real-time path.
