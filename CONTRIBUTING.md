# Contributing

Thanks for improving SentinelOps Incident Lab. Keep contributions educational, fictional, deterministic, accessible, and disconnected from real infrastructure.

## Workflow

1. Open an issue describing the learner or maintainer outcome.
2. Create a focused branch and keep changes within the agreed phase/scope.
3. Never add credentials, real personal data, executable custom scenarios, arbitrary network targets, shell execution, or offensive workflows.
4. Add tests for behavior and security boundaries. Preserve text/table alternatives for visualizations and keyboard operation for every control.
5. Run `pnpm verify`, the backend format check, OpenAPI validator, and Playwright before requesting review.
6. Update documentation and `CHANGELOG.md` for user-visible changes.

Report vulnerabilities through [the security policy](SECURITY.md), not a public issue. By contributing, you agree that your contribution is licensed under the MIT License and follows the Code of Conduct.
